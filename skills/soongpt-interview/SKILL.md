# SoongPT Interview

숭실대 시간표 추천을 위한 사용자 선호/이번 학기 전략을 3개 섹션 인터뷰로 수집.

## 트리거

- **인터뷰 시작**: "시간표 인터뷰", "이번 학기 계획 세울래", "내 선호 묻어봐", "시간표 짜기 전에 물어봐"
- **이어하기**: "인터뷰 이어서", "남은 섹션 마저"
- **조회**: "내 인터뷰 결과 뭐 있지", "지난 학기 인터뷰 복기"
- "/soongpt-interview"

## 진입 절차 (필수)

인터뷰 시작 전 두 가지 로컬 데이터를 확보한다. 어느 하나라도 빠지면 인터뷰를 시작하지 않는다.

### 1. 프로필 확인
- `get_user_profile()` 호출
- 반환 `profile`이 `null`이면 `refresh_user_profile()` 호출 (USAINT 세션 필요 — 최초엔 브라우저 로그인 폼 자동 오픈)
- 프로필이 여전히 비어있으면 사용자에게 안내 후 중단

### 2. 졸업사정표 확인
- `get_graduation_status()` 호출 — 30일 캐시 우선, 미스/만료 시 자동 fetch
- 응답의 `_cache.source`가 `"cache"`면 그대로 사용, `"fresh"`면 새로 가져온 것
- 사용자가 "새로 고쳐"라고 하면 `force_refresh=True`로 재호출

### 3. 인터뷰 진행 상태 확인
- `get_interview(year, semester)` 호출 (year/semester는 현재 학기 — 1~7월="1", 8~12월="2")
- 이미 완료된 섹션은 `completion` 맵에 bool로 표시됨
- 인터뷰가 있으면 "이어서 진행" / "처음부터 다시" 중 선택

### 4. 현재 상황 요약 (필수 — 인터뷰 첫 질문 전에 출력)

인터뷰 본격 시작 전, 사용자에게 확인차로 현재 상황을 짧게 요약해 보여준다.

**출력 항목**:
- 현재 연도/학기 (예: "2026년 1학기")
- 학과 (`profile.department`)
- 학년 (`profile.grade`)
- 학번 (`profile.student_id`)
- **남은 학기 수**:
  - 일반 학과: 8학기 기준
  - 건축학과(`department`에 "건축" 포함): 10학기 기준
  - 계산: `총 학기 - (현재 학년 - 1) * 2 - (현재 학기가 "2"이면 1, "1"이면 0)`
  - 예: 3학년 1학기 일반 학과 → `8 - 4 - 0 = 4학기 남음`
  - 예: 2학년 2학기 건축학과 → `10 - 2 - 1 = 7학기 남음`

**출력 형식 예시**:
```
현재 상황 확인:
- 학기: 2026년 1학기
- 학과: 컴퓨터학부
- 학년: 3학년
- 학번: 2021030001
- 남은 학기: 4학기 (8학기 기준)

틀린 정보 있으면 알려줘. 확인되면 인터뷰 시작할게.
```

사용자가 수정 요청하면 `set_user_profile`로 정정 후 진행. 이상 없으면 첫 섹션(`semester_strategy`)으로 진입.

## 인터뷰 3개 섹션

**한 번에 한 섹션만** 진행한다. 여러 섹션을 동시에 섞지 말 것.

- 한 섹션에 필요한 질문을 충분히 물어보고 답을 정리
- 해당 섹션만 `set_interview(year, semester, section, updates)`로 저장
- 완료 표시(`completion[section]=true`) 확인 후 다음 섹션으로 이동
- 사용자가 이전 섹션 수정을 원하면 해당 섹션으로 돌아가서 `set_interview` 재호출 (merge됨)

각 섹션을 대화로 진행하고, 마칠 때마다 `set_interview(year, semester, section, updates)`로 저장.

### 1. `semester_strategy` — 이번 학기 전략

**단일 질문**:
> "이번 학기 몇 학점 정도 들을 예정이야?"

**답변 허용 형태** (확정값 강제 금지):
- 확정 숫자: `"15학점 예정"`
- 범위: `"15~18학점 사이로 유동적으로"`
- 모름/나중에 결정: `"아직 미정, 학과 일정 보고 결정"` 또은 `"잘 모르겠어"`
- 빈 응답도 OK. 인터뷰 종료 조건은 "사용자 종료 선언" 또는 "3개 섹션 모두 어떤 형태든 저장됨"이지, 값 확정 여부가 아님.

**19.5학점 초과 안내**:
- 답이 **19.5학점 초과**인 경우 한두 줄 안내만 추가:
  > "19.5학점 초과 시 직전 학기 성적이 일정 기준 이상이거나 학점 이월 규정을 써야 신청 가능해. 잘 알고 있을 것 같지만 참고로만."
- 강제로 값을 낮추거나 다시 묻지 않는다.

**추측값 금지**:
- 사용자가 "추천해줘" 식으로 되묻면, 프로필/졸업사정표 기반 가이드만 짧이 제안(예: "보통 15~18학점을 많이 드는데, 졸업 학점 상황 보면 N학점 정도가 적당해 보여")하고 **최종값은 사용자가 결정**하도록 다시 물어봄. LLM이 임의값을 채우지 말 것.

**저장 형태**: 사용자 답변을 1~2문장으로 정리해 텍스트로 `set_interview`의 `content`에 전달.
- 예: `set_interview(2026, "1", "semester_strategy", "15~18학점 사이로 유동적으로 가져갈 예정")`

**금지**:
- 시간 투자 의향, 필수 과목 여부 등 다른 항목은 이 섹션에서 묻지 않는다.
- 19.5 안내를 길게 풀어쓰지 않는다.

### 2. `time_preferences` — 시간표 선호 + 외부 일정

시간대 선호와 외부 스케줄(아르바이트/동아리/수험 등)을 한 데 모아 잡는다. 외부 일정이 시간표의 하드 제약이기 때문.

**도입 멘트** (사용자에게 자유롭게 답하도록):
> "시간표 선호 사항 편하게 말해줘. 아래 예시 참고해서 답하고 싶은 항목만 골라 답해도 돼."

**예시 질문 (한 번에 던져주되, 사용자가 일부만 답해도 OK)**:
- 일주일에 아침 수업(9시 교시) 몇 개까지는 괜찮은지?
- 공강은 무조건 만들고 싶은지, 아니면 없어도 괜찮은지?
- 외부 활동(아르바이트/동아리/수험/인턴 등)으로 어지간하면 비워야 하는 요일·시간대가 있는지?
- 선호하는 교시대 (오전/오후/저녁), 기피하는 요일이나 교시
- 점심시간 고정 필요 여부

**저장 형태**: 사용자 답변을 자연어 요약으로 정리. 예:
> `"아침 9시 교시는 주 2개까지 괜찮음. 금요일 오후는 공강 희망. 수/금 오후에 동아리로 비워둘 것. 점심은 12시 고정."`

- LLM이 핵심만 추려서 1~5줄 내외로 정리
- 외부 활동도 요일/시간대만 잡으면 됨 (구체 장소/종류 불필요)
- 항목별로 dict/키를 만들지 말 것 — 자연어 문장이 줄바꿈/구분자로 나열된 텍스트 한 덩어리로 저장

### 3. `subject_preferences` — 과목 선호

이 섹션은 졸업사정표 컨텍스트를 같이 보여주는 게 핵심. 사용자가 자기 상황을 숙지한 상태에서 취향만 가볍게 답하도록 유도.

**진행 순서**:

**3-A. 사전 안내 (제일 먼저)**:
> "이 섹션은 무겁게 대답 안 해도 돼. 실제 어떤 과목 들을지는 뒤에 수강 가능한 시간표 보고 같이 정할 거니까, 지금은 대략적인 취향/상황만 편하게 말해주면 돼."

- 이 안내를 섹션 시작에 줌으로써 사용자가 "다 답해야 한다"는 강박을 안 느끼게.
- "몰라" / "그냥 적당히" / "비워도 돼" 같은 답 전부 허용.

**3-B. 필수 과목 질문**:
> "이번 학기에 꼭 들어야 하는 수업이 있어? (예: 선수과목 밀린 거, 졸업 필수, 장기 희망 과목 등)"

- 답 있으면 그대로 텍스트로 저장
- "없어" / "모르겠어" → 빈 문자열 또는 "특별히 정해진 필수 과목은 없음"으로 저장

**3-C. 졸업사정표 요약 제시**:
이미 1단계에서 fetch한 `get_graduation_status()` 결과에서 남은 학점/미충족 항목을 뽑아 짧게 보여줌.

형식 예시:
```
졸업사정표 요약:
- 남은 학기: 4학기 (8학기 기준) — *이미 인터뷰 시작 시 확인*
- 잔여 졸업 학점: 약 42학점
- 미충족 주요 항목: 전공심화 12학점, 교양선택 6학점, 채플 2회
```

- LLM이 알아서 `graduation_status.graduationSummary`에서 남은 학점을 뽑아 표시. 정확한 숫자가 안 뽑히면 "대략 N학점" 정도로만 안내하고 넘어감 (오차 무관).
- 남은 학기 수는 인터뷰 시작 시 이미 보여준 값 재사용.

**3-D. 취향 질문**:

- 시작 전 `get_usaint_snapshot()`을 호출해 `lowGradeSubjectCodes`(C 이하 재수강 후보)와 `subjectNames`(코드→강의명 매핑)를 확인한다. 호출 실패하거나 후보가 없으면 그냥 아래 기본 질문으로 진행.
- **재수강 후보가 있을 때**: 구체적으로 짚어 물어봄.
  > "너 C 이하 받은 과목 중에 {subjectNames로 변환한 과목명 목록}이 있던데, 이 중에 재수강 생각 있는 거 있어? 없으면 그냥 넘어가도 돼."
  - `subjectNames`에 이름이 없는 코드는 코드 그대로 표시 (폴백)
- **재수강 후보가 없거나 확인 못했을 때**: 기존 질문 그대로.
  > "그럼 이번 학기엔 대략 어떻게 듣고 싶어? 전공을 좀 더 잡을지, 교양을 좀 넓힐지 정도만 편하게 말해줘."

- 답 안 와도 OK: "특별히 정한 건 없음"으로 저장하고 넘어감.

**저장 형태**: 위 질문 답들을 자연어로 정리해 한 덩어리로 저장. 예:
```
"필수 과목: 컴파일러(선수 밀림), 운영체제.
대략 방향: 전공 비중 높게(12~15학점), 교양 3학점 정도. 재수강 없음.
취향 메모만 저장 — 구체 과목은 시간표 단계에서 결정."
```

**금지**:
- 이 단계에서 특정 과목 코드/강의명까지 확정하려 하지 말 것 (실제 시간표 안 봤으므로).
- 졸업사정표를 길게 풀어 설명하지 말 것 (핵심 3~5줄 이내).

## 저장 규칙

- 각 섹션은 **자연어 텍스트**로 저장. dict/구조화 필드 아님.
- LLM이 사용자 답변을 정리한 요약문(1~3문장, 또는 짧은 bullet 나열)을 `set_interview`의 `content` 인자로 전달.
- 같은 섹션 다시 저장하면 **덮어쓰기**(merge 아님). 수정 시엔 전체 내용을 다시 전달.
- 저장 위치: `${CLAUDE_PLUGIN_DATA}/interview_{year}_{semester}.json` (없으면 `~/.claude/state/soongpt-planner/`)

## 종료 조건

- 3개 섹션 모두 채워지면 자동 완료 안내
- 사용자가 "이대로 저장해" / "충분해" 선언 시 종료
- 종료 시 `completion` 요약 표시 후, 다음 단계(`/soongpt-available-lectures` 스킬, 시간표 후보 생성) 안내

## 비고

- 프로필/졸업사정표는 학기별 스냅샷(`profile_{year}_{semester}.json`), 졸업사정표는 단일 캐시(`graduation.json`)
- 인터뷰 결과는 후속 단계(들을 수 있는 과목 통합 조회, 시간표 후보 생성)의 주요 입력
- 재수강 후보 확인(`subject_preferences` 3-D)은 `get_usaint_snapshot()`의 `lowGradeSubjectCodes`/`subjectNames`(SPR-40) 사용 — 프로필/졸업사정표처럼 진입 절차에서 필수로 fetch하지 않고, 해당 질문 시점에만 호출
